## 3. Критерии приёмки

### Задача 1. Docker Engine

- [ ] Используется официальный Python Docker SDK.
- [ ] Подключение выполняется через `docker.from_env()`.
- [ ] Получается список контейнеров с `all=True`.
- [ ] Получаются имя, короткий ID и статус.
- [ ] IP-адрес извлекается при наличии.

### Задача 2. psutil

- [ ] Установлена библиотека `psutil`.
- [ ] Используется `psutil.net_connections(kind="inet")`.
- [ ] Получаются TCP/UDP-соединения.
- [ ] Собираются локальные и удалённые адреса и порты.
- [ ] Получаются статус и PID, если доступны.
- [ ] Обрабатываются ограничения доступа ОС.

### Задача 3. Analyzer

- [ ] Создан модуль `analyzer.py`.
- [ ] Реализована функция `analyze(containers, connections)`.
- [ ] Согласована предварительная структура JSON.
- [ ] Учтены `containers`, `connections`, `findings`, `summary` / `nodes`, `edges`, `alerts`.
- [ ] Учтены окно наблюдения и `manual_override`.

### Задача 4. Reporter

- [ ] Создан модуль `reporter.py`.
- [ ] Реализована сериализация в JSON.
- [ ] Используются `ensure_ascii=False` и `indent=4`.
- [ ] Подготовлен тест штатной работы.
- [ ] Подготовлен тест остановки контейнера.
- [ ] Подготовлен тест сетевого шума.

## 7. Порядок сдачи работы участниками

Каждый участник должен предоставить:

1. Исходный код своего модуля.
2. Инструкцию по запуску.
3. Информацию об используемых зависимостях.
4. Пример результата работы.
5. Результаты тестирования.
6. Известные ограничения и ошибки.

## 8. Правила приёмки

- Код проверяется до объединения с основной веткой.
- Pull Request должен содержать описание изменений.
- Ошибки и замечания фиксируются в журнале проблем.
- Изменения общего контракта согласовываются с командой.
- Готовность задачи подтверждается после проверки, а не только по сообщению участника.
