# INTEGRATION.md
# Zunami Network Tool — Руководство по интеграции

## 1. Назначение документа

Документ описывает порядок взаимодействия модулей проекта Zunami Network Tool, правила передачи данных, формат промежуточных результатов и обработку ошибок.

Основная задача — обеспечить совместимость между сборщиком сетевых соединений (Кейс 1) и генератором сетевых диаграмм PlantUML (Кейс 3).

## 2. Архитектура взаимодействия

Проект разделён на несколько этапов:

1. **Сбор данных (Кейс 1)** — получение информации о сетевых соединениях с помощью Python и библиотеки psutil.
2. **Обработка данных** — анализ полученных соединений, классификация узлов и формирование сетевых связей.
3. **Генерация диаграмм (Кейс 3)** — использование подготовленных данных для создания диаграмм PlantUML и экспорта в `.puml` и `.png`.

Общий принцип передачи данных:

`Network Collector → Data Processing → JSON → PlantUML Generator`

## 3. Формат промежуточных результатов (Кейс 1)

Функция сбора соединений возвращает объект с тремя основными полями:

- `result` — список успешно собранных соединений.
- `errors` — список соединений, при обработке которых возникли ошибки, с сохранением доступной информации.
- `error` — общая ошибка, если получить список соединений целиком не удалось.

### 3.1. Успешно собранные соединения

Каждая запись в `result` может содержать:

| Поле | Тип | Описание |
|---|---|---|
| protocol | string | Протокол TCP или UDP |
| local_ip | string/null | Локальный IP-адрес |
| local_port | integer/null | Локальный порт |
| remote_ip | string/null | Удалённый IP-адрес |
| remote_port | integer/null | Удалённый порт |
| status | string/null | Состояние соединения |
| pid | integer/null | Идентификатор процесса |

### 3.2. Обработка ошибок

Ошибки отдельных соединений не должны приводить к потере остальных успешно собранных данных.

Объект ошибки содержит:

- `scope` — область возникновения ошибки.
- `stage` — этап обработки.
- `code` — машинный код ошибки.
- `message` — описание ошибки.

Если отдельное поле соединения получить невозможно, оно сохраняется как `null`, а остальные доступные данные сохраняются.

### 3.3. Общая ошибка

Если функция `psutil.net_connections()` не смогла получить список соединений, возвращается:

- `result`: пустой список;
- `errors`: пустой список;
- `error`: информация об общей ошибке.

## 4. Итоговая структура данных (SCHEMA.md)

После обработки данные должны соответствовать единому контракту `shared/SCHEMA.md`.

Основные разделы итогового JSON:

### 4.1. observation_window_sec

Продолжительность окна наблюдения в секундах.

### 4.2. nodes

Список обнаруженных узлов.

Основные поля:
- `id` — уникальный идентификатор.
- `name` — название узла.
- `host` — хост-машина.
- `state` — техническое состояние.
- `status` — классификация активности.
- `traffic_level`
