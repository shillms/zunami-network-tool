# INTEGRATION.md
# Zunami Network Tool — Руководство по интеграции

## 1. Назначение

Документ описывает взаимодействие модулей проекта Zunami Network Tool.

Основная задача — обеспечить совместимость между сборщиком сетевых соединений (Кейс 1), обработкой данных и генератором диаграмм PlantUML (Кейс 3).

## 2. Архитектура проекта

Процесс работы системы:

1. Сбор сетевых соединений с помощью Python и библиотеки psutil.
2. Обработка и классификация полученных данных.
3. Формирование итогового JSON.
4. Передача JSON генератору PlantUML.
5. Создание диаграмм в форматах `.puml` и `.png`.

Общая последовательность:

`Network Collector → Data Processing → JSON → PlantUML Generator`

## 3. Формат промежуточных данных

Сборщик сетевых соединений возвращает объект с тремя полями:

- `result` — список успешно собранных соединений.
- `errors` — список соединений, при обработке которых возникли ошибки.
- `error` — общая ошибка получения списка соединений.

### 3.1. Поля соединения

| Поле | Тип | Описание |
|---|---|---|
| protocol | string | Протокол TCP или UDP |
| local_ip | string/null | Локальный IP |
| local_port | integer/null | Локальный порт |
| remote_ip | string/null | Удалённый IP |
| remote_port | integer/null | Удалённый порт |
| status | string/null | Состояние соединения |
| pid | integer/null | Идентификатор процесса |

### 3.2. Обработка ошибок

Ошибки отдельных соединений не должны приводить к потере остальных результатов.

Каждая ошибка содержит:

- `scope` — область возникновения ошибки.
- `stage` — этап обработки.
- `code` — машинный код ошибки.
- `message` — описание ошибки.

Если отдельное поле недоступно, оно сохраняется как `null`, если это допускает формат данных.

### 3.3. Общая ошибка

Если получить список соединений целиком не удалось:

- `result` возвращается пустым списком.
- `errors` возвращается пустым списком.
- `error` содержит информацию об общей ошибке.

## 4. Итоговая схема данных

Итоговый JSON должен соответствовать `shared/SCHEMA.md`.

Основные разделы:

### 4.1. nodes

Содержит информацию об обнаруженных узлах:

- `id` — уникальный идентификатор.
- `name` — название узла.
- `host` — хост-машина.
- `state` — техническое состояние.
- `status` — классификация активности.
- `traffic_level` — уровень трафика.
- `bytes_in` и `bytes_out` — объём трафика.
- `last_seen_at` — время последней активности.
- `manual_override` — ручные переопределения.

### 4.2. edges

Содержит информацию о сетевых связях:

- `source` — идентификатор исходного узла.
- `target` — идентификатор целевого узла.
- `protocol` — протокол.
- `bytes_transferred` — объём переданных данных.
- `packet_count` — количество пакетов.
- `is_external` — признак внешнего соединения.

### 4.3. alerts

Содержит предупреждения:

- `id` — идентификатор события.
- `severity` — уровень важности.
- `code` — код события.
- `message` — описание.
- `node_id` — идентификатор узла или `null`.

## 5. Правила совместимости

1. Все модули используют единую схему `shared/SCHEMA.md`.
2. Названия полей должны точно соответствовать схеме.
3. `edges.source` и `edges.target` должны ссылаться на существующие узлы.
4. Отсутствующие данные нельзя заменять выдуманными значениями.
5. Ошибка отдельного соединения не должна останавливать весь сбор.
6. Ручные переопределения должны сохраняться между запусками.
7. Промежуточный JSON сборщика не является итоговым JSON профайлера.

## 6. Порядок интеграции

1. Проверить работу сборщика сетевых соединений.
2. Проверить получение TCP- и UDP-соединений.
3. Проверить обработку ошибок и частично доступных данных.
4. Согласовать преобразование соединений в `nodes` и `edges`.
5. Проверить соответствие итогового JSON `shared/SCHEMA.md`.
6. Передать данные генератору PlantUML.
7. Проверить создание файлов `.puml` и `.png`.

## 7. Открытые вопросы

Перед окончательной интеграцией необходимо согласовать:

- Как формируются уникальные идентификаторы узлов.
- Как определяются `source` и `target`.
- Как получаются `bytes_transferred` и `packet_count`.
- Как определяется внешний трафик.
- Как ошибки промежуточного сбора преобразуются в итоговые `alerts`.

Важно: `psutil.net_connections()` предоставляет сведения о соединениях, но сам по себе не предоставляет счётчики переданных байтов и пакетов. Для этого необходим отдельный механизм сбора статистики.

## 8. Ответственность модулей

- Кейс 1 — сбор исходной информации о сетевых соединениях.
- Модуль обработки — преобразование и классификация данных.
- Кейс 3 — генерация сетевых диаграмм.
- Координация проекта — согласование контрактов, проверка совместимости и организация интеграции.

## 9. Заключение

`INTEGRATION.md` описывает взаимодействие компонентов проекта.

`shared/SCHEMA.md` является основным источником истины для структуры итоговых данных.

Любые изменения формата передачи данных должны быть согласованы между ответственными разработчиками.
