# Единый контракт данных (JSON Schema v1.0)

Этот документ описывает формат обмена данными между **Кейсом 1 (`profiler`)** и **Кейсом 2 (`visualizer`)**.
Любой JSON-файл, который выгружает профайлер и загружает визуализатор, должен строго соответствовать этой структуре.

---

## 1. Корневой объект

| Поле | Тип | Обязательно | Описание |
| :--- | :--- | :---: | :--- |
| `schema_version` | `string` | Да | Версия формата (текущая: `"1.0"`). |
| `generated_at` | `string` (ISO 8601) | Да | Время снятия слепка сети в UTC (`2026-11-26T10:30:00Z`). |
| `source` | `string` | Да | Источник данных: `"docker"` (реальный кластер) или `"emulator"` (тестовый генератор). |
| `summary` | `object` | Да | Сводная статистика по всему графу (для верхних карточек/дашборда). |
| `nodes` | `array<Node>` | Да | Список всех узлов (контейнеров и внешних хостов). |
| `edges` | `array<Edge>` | Да | Список направленных сетевых связей между узлами. |
| `alerts` | `array<Alert>` | Да | Список выявленных проблем, аномалий и «мёртвых» узлов. |

---

## 2. Объект `summary` (сводка)

| Поле | Тип | Описание |
| :--- | :--- | :--- |
| `total_nodes` | `integer` | Общее количество узлов в графе. |
| `active_nodes` | `integer` | Количество активных узлов (`status == "active"`). |
| `dead_nodes` | `integer` | Количество «мёртвых» или простаивающих узлов (`status == "dead"`). |
| `total_edges` | `integer` | Общее количество сетевых связей. |
| `total_traffic_bytes` | `integer` | Суммарный объём трафика за период наблюдения (в байтах). |

---

## 3. Объект `Node` (узел графа / контейнер)

| Поле | Тип | Обязательно | Описание |
| :--- | :--- | :---: | :--- |
| `id` | `string` | Да | Уникальный идентификатор узла (например, короткий ID контейнера или имя сервиса). |
| `label` | `string` | Да | Читаемое имя для отображения на графе (например, `"api-gateway"`). |
| `type` | `string` | Да | Тип узла: `"container"`, `"database"`, `"cache"`, `"external"`, `"unknown"`. |
| `status` | `string` | Да | Состояние узла: `"active"`, `"warning"`, `"dead"`. |
| `ip_address` | `string \| null` | Нет | Внутренний IP-адрес в Docker-сети (например, `"172.18.0.3"`). |
| `image` | `string \| null` | Нет | Docker-образ (например, `"nginx:alpine"`). |
| `ports` | `array<integer>` | Да | Список открытых/проброшенных портов (например, `[80, 443]`). Может быть пустым `[]`. |
| `metrics` | `object` | Да | Нагрузка и трафик узла: |
| ↳ `rx_bytes` | `integer` | Да | Входящий трафик (байты). |
| ↳ `tx_bytes` | `integer` | Да | Исходящий трафик (байты). |
| ↳ `connections_count` | `integer` | Да | Общее число активных соединений узла. |
| ↳ `idle_seconds` | `integer` | Да | Сколько секунд узел не отправлял и не принимал трафик (`0`, если активен). |
| `tags` | `array<string>` | Да | Теги для фильтрации в UI (например, `["backend", "prod"]`). |

---

## 4. Объект `Edge` (сетевая связь / ребро графа)

| Поле | Тип | Обязательно | Описание |
| :--- | :--- | :---: | :--- |
| `id` | `string` | Да | Уникальный ID связи (например, `"edge-1"`). |
| `source` | `string` | Да | `id` узла-отправителя (должен существовать в `nodes`). |
| `target` | `string` | Да | `id` узла-получателя (должен существовать в `nodes`). |
| `protocol` | `string` | Да | Сетевой протокол: `"TCP"`, `"UDP"`, `"HTTP"`, `"GRPC"`. |
| `port` | `integer` | Да | Целевой порт подключения (например, `5432`). |
| `status` | `string` | Да | Статус канала: `"healthy"`, `"degraded"`, `"error"`. |
| `metrics` | `object` | Да | Метрики конкретного соединения: |
| ↳ `bytes_total` | `integer` | Да | Передано байт по этому каналу. |
| ↳ `packets_total` | `integer` | Да | Передано пакетов. |
| ↳ `latency_ms` | `number` | Да | Средняя задержка в миллисекундах. |
| ↳ `error_rate` | `number` | Да | Доля ошибок от `0.0` до `1.0` (например, `0.02` = 2%). |

---

## 5. Объект `Alert` (алерты и выявленные проблемы)

| Поле | Тип | Обязательно | Описание |
| :--- | :--- | :---: | :--- |
| `id` | `string` | Да | Уникальный ID алерта. |
| `severity` | `string` | Да | Уровень критичности: `"info"`, `"warning"`, `"critical"`. |
| `type` | `string` | Да | Тип проблемы: `"dead_node"`, `"high_latency"`, `"traffic_spike"`, `"packet_loss"`. |
| `target_id` | `string` | Да | `id` проблемного узла (`Node.id`) или связи (`Edge.id`). |
| `message` | `string` | Да | Человекочитаемое описание проблемы для показа в интерфейсе. |

---

## Правила валидации
1. Все `source` и `target` в `edges` обязаны ссылаться на реально существующие `id` из массива `nodes`.
2. Если у узла `metrics.rx_bytes == 0` и `metrics.tx_bytes == 0` (или `idle_seconds > 300`), профайлер выставляет ему `status: "dead"` и добавляет запись в `alerts`.
3. Числовые поля при отсутствии данных заполняются нулём `0`, а не `null`.
